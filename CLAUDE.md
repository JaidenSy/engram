## Run isolation + tracing (worktree.py, tracing.py)
- **Every pipeline run gets its own git worktree:** `<repo>/.engram-worktrees/<run_id>` on the run's branch, cut from `origin/<pr_base>`. Every step's task JSON `repo` points at it, and tmux starts there (`-c`). On done/failed/aborted it is removed: the **branch is kept**, and uncommitted leftovers are `git stash`ed in the main repo (texted). Startup sweeps orphans. Config: `worktrees.enabled` / `worktrees.root`. `runs.single_active_run` stays `true` (abort/status still assume one live run).
- **Run state writes go through `RunEngine.update_run(run_id, fn)`**: lock held across read+mutate+write, atomic rename. Never do `get_run()` → mutate → `_write_run()` (that was the lost-update race).
- **Tracing:** each run has a W3C `trace_id` (run JSON + ledger), each step a `span_id`; the step's `claude -p` gets `TRACEPARENT=00-<trace>-<span>-01`, plus Claude Code OTel env when `telemetry.claude_code.enabled`. Secrets (OTLP headers) only via `telemetry.passthrough_env`, never config.
- **What `~/raphael/agents/run-agent.sh` (Mac Mini, not in this repo) must do:** `cd` into the task JSON's `.repo` as given (an absolute worktree path now; don't rebuild `~/Projects/<project>`); never `git checkout`/`switch` the run branch in the main checkout (git refuses a second checkout of a branch held by the worktree); don't scrub the env before `claude -p` (no `env -i`), since `TRACEPARENT`/`CLAUDE_CODE_*`/`OTEL_*` arrive via `tmux new-session -e` (needs tmux ≥ 3.0); for runs launched outside that tmux, also export the task's env: `eval "$(jq -r '.env // {} | to_entries[] | "export \(.key)=\(.value|@sh)"' "$TASK_FILE")"`. Optional: add `trace_id` to its `[TOKENS]` log line.
